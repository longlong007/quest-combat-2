# 「慢下来」慢应用 — 设计文档

> 日期：2026-05-29
> 状态：已通过需求澄清，待实现计划
> 形态：PWA（渐进式网页应用），最低成本验证概念

## 1. 愿景

帮助人们摆脱快节奏的高压生活，**夺回属于自己的时间**，回归慢生活的平衡，重新找回爱好、独处与享受生活的能力。

AI 在其中扮演**「守护者」**：守住属于自己的时间——提醒独处、挡掉打扰、保护专注与休息，而不是抢戏。

## 2. 产品一句话

一个手机端优先的"反内耗空间"。用户预约属于自己的"慢时段"，到点进入**慢模式**——AI 守护者挡掉干扰、温柔引导你去做真正想做的事，结束后做一点轻反思，沉淀属于自己的生活片段。

## 3. MVP 范围

第一版只做好一个闭环（"设时段 + 进慢模式"的结合）：

1. **设时段**：用户设定专属"慢时段"（例：今晚 21:00，时长 30 分钟，意图"读书 / 散步 / 发呆"）。
2. **进慢模式**：到点（或手动开始）进入全屏极简界面——柔和呼吸动效、专注计时、一句温柔引导语，屏蔽其他干扰元素。
3. **轻反思**：结束时记一两句"此刻的感受"，沉淀成一条"生活片段"，可回看。

### 刻意不做（YAGNI）

- 账号系统、登录
- 社交 / 社区
- 数据云同步
- 复杂统计与图表
- 真·系统级通知拦截 / 限制其他 App（网页做不到，不假装能做）

## 4. 技术架构

| 层面 | 选型 | 理由 |
| --- | --- | --- |
| 前端框架 | React + TypeScript + Vite | 生态成熟、迭代快 |
| PWA | `vite-plugin-pwa` | 可安装到桌面、离线可用 |
| 样式 | Tailwind CSS | 快速实现克制、留白的"慢"美学 |
| 状态管理 | Zustand | 轻量、心智负担小 |
| 数据存储 | IndexedDB（纯本地） | 无后端、隐私友好、契合"慢"的私密感 |
| 提醒 | Web Notifications API | 见下方限制说明 |

### 关于提醒的诚实说明

网页 / PWA 在后台可靠调度提醒的能力有限。MVP 的提醒在 App 处于打开 / 短时后台时有效；"到点强提醒"是网页能力的天花板。若未来需要可靠的后台守护提醒，需转向原生（如 Expo / React Native）。

## 5. AI 守护者（MVP 的处理）

- **MVP 先用精选引导语库**：按"意图标签 / 时段 / 时间"给出温柔文案，本地即可，零成本、零延迟、可离线。
- **预留 AI 接口**：在代码中设置"引导语生成"抽象层（如 `GuidanceProvider` 接口），未来通过配置即可切换为真实 LLM，实现个性化引导（基于用户的反思内容）。

这样可先验证"慢模式体验"是否打动人，再决定是否投入接入真实 AI。

## 6. 数据模型

```
Slot（慢时段）
  - id
  - startTime      // 计划开始时间
  - durationMin    // 时长（分钟）
  - intentTag      // 意图标签：读书 / 散步 / 发呆 / 自定义
  - reminderOn     // 是否开启提醒

Session（一次慢模式会话）
  - id
  - slotId         // 关联的时段（可空，支持临时开始）
  - startedAt
  - endedAt
  - completed      // 是否完成

Reflection（反思片段）
  - id
  - sessionId
  - text           // 一两句感受
  - mood           // 心情（轻量，如表情/几档）
  - createdAt
```

## 7. 模块拆分

各模块单一职责、接口清晰、可独立测试：

- **时段管理（Slots）**：增删改查慢时段、调度提醒
- **慢模式会话（Session）**：会话状态机（待开始 → 进行中 → 完成 / 中断）、计时
- **反思记录（Reflection）**：记录与回看生活片段
- **引导语（Guidance）**：引导文案抽象层，MVP 用本地库，预留 AI 实现
- **本地存储（Storage）**：IndexedDB 读写封装

## 8. 错误处理

- 存储失败：降级到内存状态并提示用户，避免数据丢失导致崩溃。
- 通知权限被拒：优雅退化为"页面内提醒"，不阻塞核心闭环。

## 9. 测试策略

- 单元测试：时段调度、会话状态机、存储读写、引导语选择逻辑。
- 手动走查：完整闭环（设时段 → 进慢模式 → 轻反思 → 回看）。

## 10. "慢"的体验原则（贯穿设计）

- 大量留白、柔和动效，避免红点 / 角标 / 紧迫感。
- 不做"连续打卡天数"等会制造新焦虑的机制。
- 文案温柔、非命令式，给用户掌控感而非被驱使感。
